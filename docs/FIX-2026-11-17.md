# 3005 保存恢复与模型请求限制

## 用户再次反馈 Saving 后的追加修复

上轮只验证读取报错，没有覆盖永不回调的等待，不能视为已解决用户截图中的实际故障。这轮增加：

- 封面异步解码最多等待 1.5 秒，失败或一直等待时沿用旧封面，正文与媒体原件继续保存；新建与保存共用此流程。
- 工程准备等待 60 秒后明确报错并取消媒体读取；数据库打开等待 10 秒，写入等待 60 秒后中止事务，保留原记录并允许重试。超时表示未确认保存成功，不假报成功。
- 使用每次独立打开的存储连接，避免复用永不结束或失败的打开 Promise；监听数据库被阻塞、事务中止和读取失败。
- React Fast Refresh 更换存储实例时取消旧保存，清理旧 Promise 与 Saving 状态，保留活动工程并重试当前画布内容。
- 保存面板显示“正在准备工程内容”或“正在写入工程”，便于区分等待位置。
- 缺少 Blob 的纯本地图片集合按二进制保存，避免不必要的 base64 转换。

追加验证：扩展的 `verify-save-recovery.mjs` 全部通过，包含真实 IndexedDB 打开无回调、保持事务活动但读取无回调、事务取消后旧数据完整及重试、封面解码永不结束时实际保存按钮完成并刷新恢复 64×64 图片，以及真实 React Fast Refresh 保留并保存当前工程。`verify-browser-projects.mjs` 的授权文件夹完整流程通过；227 项 Node 测试及构建通过。未直接接管用户浏览器页面，不能仅据隔离验收宣称用户现有工程已保存成功。

## 工程保存

局域网 HTTP 使用当前浏览器 IndexedDB，HTTPS/localhost 的授权文件夹流程不变。基础新建、保存、导出与刷新恢复原本可通过；尚未取得用户当时的具体报错，不能确认下列缺陷就是该次故障的唯一原因。

- 替换工程原子更新入口：原 `idb-keyval.update` 在读取请求失败或事务提前中止时可能永不结束，使保存一直等待。新入口监听读取和事务错误，失败后可重试，不覆盖原文档。
- 若累计快照导致存储配额不足，进行一次原子重试，仅保留最新完整快照并明确提示导出备份；原保留数量设置不变。重试仍失败则原数据与快照均保留。空间紧张时历史快照会减少。
- 缺少 Blob 的临时媒体链接在保存和导出时转换为持久内容，避免静默清空主图片或保留刷新后失效的图库链接。读取失败会中止保存。

## 模型限制

运行日志确认同账号三个模型请求进行时，新请求在本地转发前返回 `503 concurrency_limit`。这属于同时请求数限制，没有发现累计生图次数配额。

本机 `.env.local` 开启 `CANVAS_UNLIMITED_MODEL_REQUESTS=true`，使登录后的 `/api/model-request` 不受本地全站/账号并发及频次拒绝限制。后台显示已解除，画布批量调度仍使用管理员的并发配置；供应商额度、余额与速率限制不变。其他实例默认保持原限制，登录验证、请求超时和账户隔离仍适用。模型配置修订号不变时，前端也会同步有效并发数变化。
