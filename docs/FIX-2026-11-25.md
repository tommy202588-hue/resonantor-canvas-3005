# 3005 首页读取工程卡住、新建按钮禁用

用户截图中已登录，但首页一直显示“正在读取…”，新建与导入按钮禁用。服务和首页 HTTP 正常。代码确认：列表仍通过 idb-keyval 缓存连接读取 keys/get，没有超时，且按钮被 loading 全局禁用。未直接读取用户浏览器数据库，实际导致浏览器读请求挂起的底层原因未确认。

## 修改

- 工程列表、工程打开、目录授权记录恢复和草稿读取改用独立数据库连接，监听读请求失败、事务中止和超时；关闭连接，不删除原数据。
- 首页整体读取最多等待 15 秒，失败显示重试提示并保留已显示的工程；单条无法读取时给出警告并继续列举其他工程。
- 局域网浏览器存储模式下，新建及导入不再等待列表完成。实际写入成功才进入新工程，写入失败仍明确报错。
- 创建或保存更新工程后使旧列表请求失效，防止迟到的列表结果覆盖新工程；账号切换或重试时取消旧读取。

- `scripts/verify-save-recovery.mjs`：保存错误恢复、超时取消、媒体持久化、封面卡住、热更新恢复全部通过。
- `scripts/verify-browser-projects.mjs`：授权文件夹、创建、保存、重开、账户隔离及草稿恢复全部通过。
- 23 项相关 Node 测试通过，`npm run build` 通过，局域网 HTTP 200。

修复已由 3005 Vite 热更新加载。未重启服务，未清除用户浏览器存储，未调用付费模型，未变更 3004。

## 后续反馈：创建弹窗停在“处理中”

新增的 `scripts/verify-create-refresh.mjs` 在修复前实测复现：新建过程中 React Fast Refresh 更换 storage 后，旧操作的 finally 因 isCurrent 为 false 跳过清理，busy 与 transition 永久保留，后续 create 返回 false，画布从未打开。修复前输出为 stuck=true、retried=false、shown=0。

修复后在 storage 更换时中止旧创建并释放 busy/transition；为新操作添加独立控制器，旧操作不能解除新操作的状态。创建动作也会取消过期的列表读取，防止列表结果覆盖创建状态。空白工程全流程 20 秒等待上限，导入工程 90 秒；取消信号传给浏览器写入事务，失败不会假报成功。弹窗明确显示准备内容、连接工程存储或等待写入。

验证：同一 Fast Refresh 复现测试改为 stuck=false、retried=true、shown=1；真实创建弹窗模拟永不返回的事务读取，20 秒内报错并恢复按钮、事务确认中止且没有半成品记录，重试成功并刷新重开。构建与 23 项相关 Node 测试通过；列表、保存与文件夹授权浏览器回归通过。没有直接操控用户的现有 Chrome 页面，因此热更新缺陷的复现不等于已确认用户当前浏览器数据库健康。
