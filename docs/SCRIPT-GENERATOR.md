# 脚本生成器

## 入口与流程

登录并打开画布工程后，点击左侧书本图标「脚本生成器」，或在画布右键 → 添加节点 → 脚本生成器。卡片上的「打开脚本节点 →」和双击卡片均可打开三步工作台。创建时选中的文本节点会作为初始原稿，不修改原节点。

1. **确认镜头**：上传 TXT、MD、SRT、Fountain 文本，或粘贴原稿。UTF-8、带 BOM 的 UTF-16 和 GB18030 可读取。文件最大 512 KB，正文最多 40000 字符，不截断；Word / PDF 请导出 TXT 或复制正文。选择目标镜头数（1–40），调用后台文本模型生成分镜与角色/场景/道具清单。镜头表支持时长、画面、景别、光影、对白、音效、运镜、资产关联、复制、删除和排序。核对后确认镜头。
2. **准备资产**：编辑全局风格、名称和外观设定，新增或删除角色、场景、道具。上传 PNG/JPG/WebP，或使用后台图片模型生成单项/全部缺失资产。每次批量生成前确认 API 费用。参考图最长边处理为 1536px，并嵌入工程，不依赖易失效的 blob URL。原始文件不被修改；生成中按顺序处理，遇错停止，已完成的资产保留。
3. **合成提示词**：每批最多五个镜头，调用后台文本模型，合并分镜、关联资产文字设定和全局风格。缺失图片时可先生成文字提示词，不谎称已看过图片。支持逐镜重生成、编辑和导出分镜 JSON。

修改分镜、原稿、资产或风格会使提示词失效；修改镜头内容需要重新确认。错误或不完整的模型 JSON 不覆盖已有内容。

**分镜生成支持退出编辑界面等待**：点击右上角关闭按钮、按 Escape 或点击「返回画布等待」，请求仍由当前画布页面执行，结果按节点与任务 ID 回写，不依赖弹窗是否打开。再次打开可查看状态，运行中不允许重复生成或改动原稿。节点显示步骤百分比：0% 校验中、25% 原稿校验完成/等待模型、50% 模型返回、75% 分镜校验完成、100% 结果写回节点。百分比不是模型生成字数或预计时间；非流式模型等待阶段保持 25%，不使用计时器虚增进度。失败显示错误，可打开原稿重试。

这里只支持关闭脚本编辑界面，不是服务器持久任务。请保持网页打开；刷新/关闭网页会提示未完成任务，恢复工程后将无法续接的任务标记为中断，保留原稿与已有分镜，绝不自动重试以避免重复费用。已有图片资产生成和提示词合成仍使用编辑界面内任务；批量任务可停止后续请求，但已提交请求需等待完成。

## 返回画布

- 「发送文本节点」：把已完成的提示词变成独立文本节点。
- 「发送视频节点」：全部镜头确认且提示词完整后，创建待生成视频节点，带上镜头提示词、时长、后台默认视频模型；关联参考图作为共享图片节点连接到对应视频节点。
- **不自动发起付费视频批量生成。** 用户先在视频节点核对提供商支持的时长、分辨率、参考图数量，再使用现有画布生成按钮。此功能不包含自动剪辑成片。
- 脚本原稿、步骤、镜头、资产图和提示词进入原有工程保存/自动保存、JSON/JS 导入导出和浏览器草稿机制。分镜 JSON 是独立交付数据，不是完整画布工程文件。

## 后台模型

通过既有 managed provider 和 /api/model-request 调用模型，不在新节点放置密钥输入框，不向浏览器下发真实凭据。

管理员在 /admin/models 的**文本模型**里添加可用模型与密钥，再在图片/视频分类设置所需模型。页面复用现有自动同步机制。未配置文本模型时可上传、保存原稿并手工编辑镜头，AI 按钮禁用且显示明确提示。

2026-09-15 本机检查：文本模型提供商为 0，图片模型提供商为 2。本次未擅自修改后台配置，也未消耗真实 API 额度。真实剧本生成效果需管理员配置文本模型后验收。

## GitHub 调研

用户要求查找高度相近的 skill。已通过 GitHub 官方仓库 API 和原始 README 核对：

- https://github.com/zenstory-ai/drama-skills ：MIT；包含 assets、storyboard、image-prompts、video-prompts 等 Agent Skills，生产前确认的工作流相近，但以 Agent CLI 和文件为核心，不是 React 画布组件。
- https://github.com/eternityspring/shuohao-skills ：Apache-2.0；包含角色、美术资产、剧本、分镜技能与 HTML 报告组装器，同样不是可直接嵌入此画布的交互节点。
- https://github.com/chatfire-AI/huobao-drama ：完整独立短剧平台；GitHub API 对许可证返回 NOASSERTION，未据此复制代码或引入整套服务。

本实现采用同类流程的通用拆分思路，按用户四张参考图原生实现，不复制上述仓库代码或提示词，不自动安装/执行外部 Skill，也不引入它们的独立服务依赖。
