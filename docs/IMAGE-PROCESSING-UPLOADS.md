# 图像处理上传

画布去背景和高清放大使用二进制上传：

- POST /api/upscale/jobs?jobId=UUID&mode=remove-background&scale=1
- Content-Type: application/octet-stream
- 请求体为原始图片 Blob，不转换为 Base64，也不再执行原先的 22 MB 文件检查。
- 服务端校验来源、任务归属和模式后，持有单任务提交锁，将请求流直接写入该任务的 source.png。向 ComfyUI 上传预处理图片使用文件支持的 Blob，避免完整复制到内存。
- 空文件和中断上传会清理部分文件并释放提交锁；Python 仍验证实际图片格式。任务重试使用新任务 ID。
- 旧版 JSON/Base64 请求继续兼容，其 JSON 请求体保护限制不变；当前画布不再经过该上传路径。
- 去背景保持原尺寸；高清放大不再限制输入 2048px、输出长边 8192px 或 3200 万像素，按 2× / 4× 计算并验证实际结果尺寸，不主动缩小图片。4800 × 6400 的预计输出分别为 9600 × 12800 和 19200 × 25600。
- 新放大任务使用 SeedVR2 v2.5.1，读取图片宽高后计算目标短边为原图短边 × 所选倍率，max_resolution=0。2× 和 4× 均直接在目标尺寸推理，不再使用 Real-ESRGAN 4× 后缩小的工作流。固定分辨率控件不参与计算；不静默封顶后插值补尺寸。
- 读取 ComfyUI 结果时，Python 的图片像素保护阈值仅针对当前任务的预期输出尺寸调整，读取后恢复；仍在解码前拒绝尺寸不匹配的结果，原图解码保护不变。
- 不承诺无限文件处理能力：浏览器、磁盘、内存、显存、请求超时和 ComfyUI 自身的上传配置仍可能影响处理。大图可能因资源不足失败，不自动降低尺寸或改用其他模式。

回归测试包含 40 MiB 分块上传（两种模式）、任务隔离、防重复、空文件及上传中断。不访问真实 GPU 或用户工程目录。
