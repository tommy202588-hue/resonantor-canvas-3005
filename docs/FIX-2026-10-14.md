# 3005 本地验证记录：并发限制与局域网工程创建

本次改动只在 `main-3005-isolated`，未发布官网，未修改 3004。

## 生图返回 503 concurrency_limit

- 该错误由画布自身的代理并发检查返回，发生于模型转发之前，不能据此判断 API 密钥或余额异常。
- 3005 实际保存的批量并发数为 15；未覆盖环境变量时，代理全站上限为 8，单账号模型请求上限为 3。配置项 `MAX_CONCURRENCY_PER_IP` 在 `/api/model-request` 中实际按登录用户 ID 计数，其他代理路径仍按连接来源计数。
- 同一账号已经有三个请求进行时，第四个请求会返回 503；正常成功或失败会释放名额。图片、视频、文本、音频及同账号其他页面都会影响可用名额。
- 用户提供的 requestId 未在本地日志检索到，未读取官网运行配置或日志，不能断言官网那次请求具体触发了账号限制还是全站限制。

修复后，普通画布收到的批量并发数为后台配置值、账号上限和全站上限的最小值；后台保留用户配置，并显示实际代理上限。修改运行上限后，即使模型配置修订号未变，画布也会更新有效并发数。

模型请求增加从读取请求体开始的总等待上限，默认 300000 毫秒。浏览器断开时，代理停止等待并中断上游连接；超时或异常均释放名额。中断连接不代表供应商已取消远端计算或费用；代理不会因此自动重发生成请求。

503 提示现在区分账号、全站及上传并发限制，带 `Retry-After: 10`，日志包含 `errorType`、`limitScope`、活动请求数量与 requestId，不记录提示词、图片或密钥。客户端断连在日志中标记 499。

对于尚未更新的实例，可暂时把后台“画布批量并发数”设为 1–3，停止连续点击，等已提交请求结束后再手动提交。若所有用户一直受阻，应结合 requestId 检查运行日志及代理超时；不能仅提高前端并发数来解决。提升全站上限需结合内存、供应商配额和账号上限统一配置。

## 局域网 HTTP 不能创建工程

旧逻辑要求文件夹授权为 ready 才能创建，但局域网 HTTP 没有 `showDirectoryPicker`。现在不支持该接口时，使用当前电脑浏览器的 IndexedDB 保存工程，按账号和网站来源隔离，直接启用创建；HTTPS/localhost 支持文件夹时继续使用原授权流程。

- 新建即保存，默认每五分钟保存并保留五份快照；支持 Auto save 设置、重命名、导入、导出和刷新后重新打开。
- 工程不会写入服务器，也不会自动写入桌面。界面明确显示保存位置以及清除网站数据会丢失工程，用户可通过“导出项目”下载独立备份。
- 存储更新使用 IndexedDB 原子事务，拒绝过期修订，写入失败不删除上一次完整数据。切换账号清除当前视图并保留原账号草稿，防止后完成的操作写入另一个账号的界面。
- 删除操作从最近工程列表隐藏记录，保留本地存储中的快照；已导出的文件可重新导入。
